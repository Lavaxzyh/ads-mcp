# 源码发布与运行数据边界

本分支发布源码、通用配置示例和合成测试输入，不发布维护者的 ADS 原工程、器件模型库、许可证、账户凭据、聊天记录、原始验证日志或机器配置。上游仓库已经公开的示例与历史文件保留原有出处，不能据此推定已在 ADS 2025 重测。

`HPEESOF_DIR`、`ADS_MCP_WORKROOT`、`ADS_MCP_STATE_FILE` 由使用者在自己的客户端环境配置。文档中的 `<ADS_INSTALL>`、`<REPO>`、`<TASK_ROOT>` 和 `C:/ads-mcp-example/` 是示例，需要替换；它们不是维护者机器的真实目录。

源码不包含云端模型 API 密钥，也不负责选择 MCP 客户端使用的云模型。Keysight 模块来自使用者已授权的本机 ADS 安装，不能从此仓库获取 ADS 本体、许可或第三方模型。

## 运行时仍会生成本地敏感资料

- GUI 桥接需要本机生成的认证材料，例如 `.ads-mcp/gui/**/credential.json`。这些文件是运行必需的本地凭据，不应提交到 Git 或随工程发送。
- 自检、任务状态、报错、网表、CSV 和结果清单可能包含本机路径、计算机名、进程信息、模型名或工程参数。它们默认写入用户指定的输出目录；源码分享检查不会自动匿名化以后产生的运行结果。
- MCP 工具结果会交给当前客户端。客户端是否向云模型发送内容由其配置和使用者授权决定，不能把“本机仿真”理解为“任何结果都不会离开电脑”。
- 分享仿真数据前应另行检查内容与模型授权。不要通过删除运行中的凭据、锁文件或任务记录来进行脱敏，先确认任务终态，再制作独立分享副本。

`.gitignore` 排除常见运行记录、凭据、配置和数据扩展名；它不能撤销已跟踪文件或替代人工检查。发布包只从已审核的 Git 文件清单生成，排除 `.git`、虚拟环境、运行目录和私有审计记录。

## Git 身份

提交应使用公开 GitHub 用户名和 GitHub 的 `noreply` 地址，不需要写入私人邮箱、Windows 用户名或学校信息。远程地址使用普通 HTTPS 仓库地址，不把令牌嵌入 URL。历史提交沿用上游已公开记录，不伪造或重写原作者署名。
